# QA Review — Correctness, Functionality & Robustness

**Project:** creative-puzzle-studio
**Commit reviewed:** `d7f074a` (working tree clean)
**Date:** 1 November 2026
**Method:** full source read of every route, hook and game component; static analysis of the built CSS;
automated runtime interaction audit (9 routes × 4 viewport/theme combinations, clicking every control in
isolation); targeted functional assertions in a real browser.

**Evidence key** — `[runtime]` = reproduced in a headless browser against the production build.
`[code]` = verified by reading the source; not reproducible here because it needs a live Supabase session.

---

## 1. Verdict

The app is **structurally sound and navigable**: every route loads, every lazy chunk resolves, no route
throws, and no interactive control crashes. There are **no broken links and no console errors** on any
route (the one console message on the 404 page is deliberate diagnostic logging).

The defects are concentrated in the **game-result pipeline** — how a finished (or unfinished) run becomes a
score, and how that score reaches the leaderboard. Five High-severity issues sit there, and three of them
can silently corrupt the leaderboard.

| Severity | Count |
|---|---|
| High | 5 |
| Medium | 10 |
| Low | 15 |
| **Total** | **30** |

## 3. High severity

### H1 — A timed-out attempt is recorded as *completed* and enters the all-time leaderboard
**Location:** `src/pages/GameEnhanced.tsx:174-181` · `src/pages/Results.tsx:34`
**What's wrong:** the time-up effect calls `updateScore(finalScore, incorrectAttempts, elapsedMs, true)` —
the last argument is `completed`, hardcoded `true`. `Results.tsx:34` only skips the leaderboard write when
`!currentPlayer?.completed || score === 0`, so any timeout with a non-zero score is persisted to the
all-time board. `Results.tsx:227` then renders an "Incomplete" badge, contradicting the flag it just wrote.
**Symptom:** students who never finished inflate the leaderboard, and the teacher dashboard reports them as
"Finished".
**Evidence:** `[code]`

### H2 — The leaderboard double-counts on revisit, refresh, or any player event
**Location:** `src/pages/Results.tsx:33-69`
**What's wrong:** the save effect depends on `[currentPlayer]`. `useGameSession` replaces `currentPlayer`
with a **new object** on every `fetchSession()`, and the realtime subscription (`useGameSession.ts:63-70`)
calls `fetchSession()` on *any* `game_players` change — including the student's own score write. The effect
also does a read-modify-write (`existing.total_score + currentPlayer.score`) with no transaction and no
idempotency guard.
**Symptom:** every visit to `/results/:id`, every reload, and every player event adds the score again.
Totals grow without bound. Two tabs open → worse.
**Evidence:** `[code]`

### H3 — The final score is silently discarded if `currentPlayer` hasn't loaded
**Location:** `src/hooks/useGameSession.ts:199-214` · `src/pages/GameEnhanced.tsx:183`
**What's wrong:** `updateScore` begins `if (!currentPlayer) return;` — no retry, no error, no queue.
`currentPlayer` is only populated inside `fetchSession`, and only when `userId` was already non-null.
`GameEnhanced.tsx:183` also returns `null` for a game master *before* the null-session guard.
**Symptom:** a student finishes, sees the celebration overlay and a score, but nothing is persisted; the
results page then shows 0 points and "Incomplete". Silent data loss at the most important moment.
**Evidence:** `[code]`

### H4 — Pause/resume corrupts the elapsed timer and inflates the score
**Location:** `src/pages/GameEnhanced.tsx:62-76`
**What's wrong:** the timer effect depends on `[isPaused]` and its first statement is
`startTimeRef.current = Date.now()`. That runs on the **resume** render too, resetting the start time, while
`pausedAccumulatedRef` *also* adds the pause duration. The formula
`Date.now() - startTimeRef.current - pausedAccumulatedRef.current` therefore subtracts the pause twice and
loses all pre-pause time.
**Symptom:** after any pause, the clock resets to ~0 and briefly goes **negative** (`formatTime` renders
`-1:-5`). `calculateJigsawScore` then subtracts a negative time penalty, inflating the score — which feeds
straight into H2.
**Evidence:** `[code]` — needs a live session to drive, but the arithmetic is unambiguous.

### H5 — `/dashboard/:id` is a blank page when the session can't load
**Location:** `src/pages/TeacherDashboard.tsx:132-143`
**What's wrong:** `if (!session) return <spinner />` with no error branch and no `loading` check. Every
other data route (Lobby, Results, GameEnhanced) has a proper not-found/error state; this one does not.
**Symptom:** the teacher sees an empty page with a spinning icon, forever. No message, no navigation.
**Evidence:** `[runtime]` — `/dashboard/nope` → `buttons = 0`, `body text = ""`.

## 4. Medium severity

### M1 — Dark theme is lost on 6 of the 9 routes
**Location:** `src/hooks/useTheme.ts:12-20`; theme is only initialised as a side effect of `useTheme()`,
which only runs when a `ThemeToggle` mounts. Toggles exist only in `Index`, `GameEnhanced`,
`TeacherDashboard` (and the dead `Game.tsx`).
**Symptom:** deep-linking or refreshing on `/lobby`, `/results`, `/leaderboard`, `/teacher/login`,
`/lab07/game` or the 404 page renders **light** despite a stored `dark` preference. On `/` the theme is
applied only after auth settles (~2.3 s offline), so there is a visible flash of light theme.
**Evidence:** `[runtime]` — with `puzzle-theme=dark`, `html.className` was `""` on all four routes tested;
after a reload of `/` it was still `""` at 1.2 s.

### M2 — Every player event triggers a full refetch and a full-page spinner
**Location:** `src/hooks/useGameSession.ts:63-70` (realtime → `fetchSession`), `:19` (`setLoading(true)`),
`:32-37` (re-reads *all* players). `Lobby.tsx:57` and `Results.tsx:94` render a whole-page spinner whenever
`loading` is true.
**Symptom:** the lobby flashes a full-page spinner on every student join; the results page flickers on
every score update. With *N* students placing ~16 pieces each, that is *N*×16 full-table refetches
broadcast to every connected client.
**Evidence:** `[code]`

### M3 — `difficulty` does not change the grid, contradicting the instructions
**Location:** `src/lib/gameData.ts:160-171` — `rows = 4; cols = 4` for every level; `lvl` is computed and
never used. `InstructionsModal.tsx:87` states "Easy = smaller grid, Hard = larger grid".
**Symptom:** difficulty only affects the time limit and point multiplier. The how-to-play text is wrong.

### M4 — The decoy/filler mechanic is effectively dead
**Location:** `src/components/game/JigsawImagePuzzle.tsx:140-176` · `src/lib/gameData.ts:177-185`
**What's wrong:** the grid has 12 quote slots and there are exactly 12 base quotes (4 stages × 3). Each
column consumes all 3 quotes of its stage, so `correctQuotes` covers the entire pool and `fillerPool` is
empty. `sampleRandom([], n)` returns `[]`. `numFiller = (level - 2) * 2` is also 0 on easy and medium.
**Symptom:** "Some quote pieces are decoys (wrong) — avoid placing them!" is false in every game, except
for at most **one** leftover quote in hard/very-hard *and* only when the student supplied a best-ideas
answer.

### M5 — "Load Puzzle" instantly declares victory
**Location:** `src/components/game/EightPuzzleLab.tsx:76-79`, `:71-74`, `:194-201`
**What's wrong:** `handleLoadPuzzle` sets the solved tile order and `loaded = true`; `isSolved` is then
true, so the "🎉 Puzzle solved!" overlay renders immediately.
**Symptom:** clicking Load Puzzle looks like an instant win; the player must click Shuffle to actually play.
**Evidence:** `[runtime]` — overlay count went 0 → 1 immediately after the click.

### M6 — Clipboard copy throws instead of falling back on insecure origins
**Location:** `src/pages/Lobby.tsx:41-55` · `src/pages/TeacherDashboard.tsx:35-48`
**What's wrong:** `navigator.clipboard` is `undefined` outside a secure context. `navigator.clipboard.writeText(url)`
throws **synchronously**, so the `.catch()` fallback never runs and the success toast still fires.
**Symptom:** on any `http://` deployment (a classroom LAN, for example) the invite link is not copied but
the UI says "Invite link copied!".

### M7 — Leaderboard query errors render as "no games played"
**Location:** `src/pages/Leaderboard.tsx:19-30` — `const { data } = await supabase…`, error discarded.
**Symptom:** a network or RLS failure shows "No games played yet. Be the first!" — indistinguishable from a
genuinely empty board.

### M8 — Game-control writes ignore their errors
**Location:** `src/hooks/useGameSession.ts:154-196` — `startGame`, `endGame`, `togglePause`,
`updateDifficulty`, `kickPlayer` all `await` a Supabase update and discard the result.
**Symptom:** "Start Game" does nothing and says nothing when the write fails; the teacher retries blindly.

### M9 — CSV export is unescaped and formula-injectable
**Location:** `src/pages/TeacherDashboard.tsx:93-113`; nickname input `src/pages/Index.tsx:513` (no
character restriction).
**What's wrong:** `"${p.nickname}"` never doubles embedded quotes, and a nickname beginning with `=`, `+`,
`-` or `@` becomes a live formula when the file is opened in Excel or Sheets.
**Symptom:** malformed CSV; spreadsheet formula injection from untrusted student input.

### M10 — Score writes are blind overwrites (last-writer-wins)
**Location:** `src/hooks/useGameSession.ts:199-214` — `.update({...}).eq("id", currentPlayer.id)` with no
compare-and-set.
**Symptom:** with two tabs open, the second completion overwrites the first score instead of the better one
being kept.

## 6. Test coverage

The `npm test` gate reports **4/4 passing**, but the suite is:

- 3 tests for `normalizeBestIdeasAnswer` (trim, truncate, whitespace-only)
- 1 placeholder: `expect(true).toBe(true)`

There is **no test** for `calculateJigsawScore`, `getLevelGridConfig`, `getRandomizedStagesForPlayer`, the

## 7. Recommended fix order

1. **H3** first — it is silent data loss, and it makes every other result bug harder to observe.
2. **H1 + H2 together** — they share the same write path. Introduce an explicit `finished` vs `timed_out`
   outcome, and make the leaderboard upsert idempotent (a unique key per player per session, or an RPC with
   a `ON CONFLICT DO UPDATE`).
3. **H4** — split the timer effect so `startTimeRef` is set once on mount, and derive elapsed from
   `now - start - accumulatedPaused`.
4. **H5** — add the missing error branch to `TeacherDashboard`, mirroring `Results.tsx:105-119`.
5. **M1** — hoist theme initialisation to a single app-level effect (or an inline script in `index.html`)
   so it is applied before first paint on every route.
6. **M2** — stop setting `loading` on refetch, and update players incrementally from the realtime payload
   instead of re-reading the whole table.
7. **M4 / M3** — decide whether difficulty should scale the grid and whether decoys are meant to exist;
   then make the code and the instructions agree.
8. Add tests for the scoring and completion paths before touching anything else in that area.

## §12 — Follow-up pass: unused-dependency closure + end-to-end proof

### What was still open

The release table closed seven items, but one thread was unfinished: the unused-dependency chain.
`zod`, `date-fns` and `@hookform/resolvers` were flagged, and tracing them showed the chain was
wider — `react-hook-form` and `react-day-picker` were consumed **only** by `ui/form.tsx` and
`ui/calendar.tsx`, neither of which was imported anywhere. Fixing three packages would have left the
same problem two layers down.

### How the closure was computed

Rather than counting imports per file, the whole module graph was walked from `src/main.tsx`
(resolving `@/` and relative specifiers, `.ts`/`.tsx`/`index` variants) and intersected with every
file under `src/`. Anything unreachable from the entry point is dead by construction. The walk also
included tests, `src/test/setup.ts` and the tool configs so that dev-only packages were not
misclassified.

**Result: 36 unreachable files** — 34 `components/ui/` primitives, `use-toast.ts` and
`use-mobile.tsx`. `src/test/setup.ts` is loaded by `vitest.config.ts`, not by the entry point, and is
excluded from that count.

### What was removed

| Item | Before | After |
|---|---|---|
| Runtime dependencies | 48 | **20** |
| `components/ui/` primitives | 46 | **12** |
| Unreachable source files | 36 | **0** |
| Production advisories (`npm audit --omit=dev`) | 12 | **2** |

Packages dropped because only dead files used them: 21 `@radix-ui/*` packages, plus `cmdk`,
`embla-carousel-react`, `input-otp`, `react-resizable-panels`, `recharts` and `vaul`.
`@tailwindcss/typography` was a devDependency that was never registered in `tailwind.config.ts` and
had no `prose` classes — also removed.

Two dependency corrections that were not strictly "unused" but were in the wrong place:

- **`tailwindcss-animate` moved to `devDependencies`.** It is a Tailwind plugin, imported only by
  `tailwind.config.ts`, but it was declared as a runtime dependency — which dragged `tailwindcss`,
  `postcss` and their transitive trees into the production graph. That single move cleared 10 of the
  12 advisories.
- **`ws` pinned to `^8.22.1` via `overrides`.** `@supabase/realtime-js` ships `ws@8.19.0`, which has
  an uninitialised-memory disclosure and a memory-exhaustion DoS. A patch-level bump inside the same
  major is safe.

### The end-to-end proof

No test in the suite ever put a piece on the board — key placement, the phase transition, quote
matching and completion were verified only by eye. `src/test/jigsaw-flow.test.tsx` now drives the
real `JigsawImagePuzzle` through a complete Easy game and a Hard decoy game.

Three jsdom behaviours had to be understood before the test could be written honestly:

1. **A placed cell changes its `aria-label`** from `Key slot 1` to `Placed: <statement>`. Any list of
   cells built by label silently shifts after the first placement — this is what made the first
   draft of the test fail while the component was correct. Cells are now captured by reference once.
2. **The tray removes placed pieces through a Framer Motion exit animation**, which never completes
   under jsdom, so a placed piece's button lingers in the tree. "Has this piece been placed?" is
   answered by the cell's label, never by the piece's absence from the tray.
3. **Phase 1's tray only lists key pieces**, so decoys do not exist in the DOM until the key row is
   complete — the decoy test must clear the keys first.

A fourth: Framer Motion's `popLayout` calls `window.scrollTo`, which jsdom does not implement. That
flooded the output with "Not implemented" noise that is not a failure and hides real ones, so
`setup.ts` now stubs it (nothing in the app scrolls programmatically).

Assertions: 4 keys placed, `onPhaseComplete` once, all 8 quotes matched to their column, every
deliberate wrong-column tap rejected **and** the cell left empty, `onPiecePlaced` exactly 12 times,
`onIncorrect` exactly the number of wrong taps, all 12 cells filled, `0 left`, `onCompleted` exactly
once (re-checked after 900 ms to prove it cannot double-fire). The decoy test proves two decoys are
refused in all 16 quote cells with zero placements.

### Root cause of the recurring `ENOTEMPTY` failures

Every `npm install`/`npm prune` in this project was failing with:

```
ENOTEMPTY: directory not empty, rename 'node_modules/caniuse-lite'
        -> 'node_modules/.caniuse-lite-BKiTLWYR'
```

This was not a flaky install. A **stale temp directory** `.caniuse-lite-BKiTLWYR` from a failed run
months earlier was still on disk, so npm's rename had a non-empty destination. Removing that
directory fixed installs permanently — earlier passes had worked around the symptom with
`npm pkg delete` + `npm install --package-lock-only`, which left orphaned packages in
`node_modules`.
